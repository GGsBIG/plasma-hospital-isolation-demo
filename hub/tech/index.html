Plasma 元件總覽

Plasma 用一個 Web 介面管完整段資料流程：連上來源資料庫、用 SQL 查詢與轉換、排程寫出，最後發布成資料產品或 MCP 工具給 AI 使用。以下依資料流的順序，說明每個元件做什麼、規格與限制。

01

工作區Workspaces

每個工作區是一個獨立容器，裝著自己的連線、View、資料產品、Blueprint 與排程。不同部門各用一個工作區，資料與設定互不干擾；要共享時，再把 View 發布成資料產品。

規格

  • 成員角色：Owner、Manager、Member
  • 每個帳號都有私人工作區 user_<使用者名稱>
  • 系統管理員在所有工作區都等同 Owner

限制

  • 角色只管工作區本身（詳情、成員名單），不限制工作區內的一般操作
  • 私人工作區不能共享，也不能刪除

02

資料庫連線Database Connections (DBC)

告訴 Plasma 怎麼連上外部的關聯式資料庫。連上後 Plasma 會發現資料表，可以直接在 SQL 編輯器查詢，也能當 View 的來源或 Blueprint 的寫入目的地。

支援的資料庫

資料庫讀取寫入
Oracle✓✓
SQL Server✓✓
PostgreSQL✓✓
MySQL／MariaDB✓✓
Informix✓唯讀
Db2 for i（AS/400）✓唯讀

規格與限制

  • 狀態：Preparing → Syncing → Ready，或 Failed
  • Syncing 期間不能 Edit 或 Sync
  • 連線只屬於一個工作區
  • Db2 只支援 IBM i，LUW、z/OS 版本不支援
  • 查詢寫法：<連線名稱>.<資料表>

03

StreamingStreaming Source · Streaming Sink（選用）

讓工作區裡的資料表跟來源資料庫持續同步，逐筆套用新增、更新、刪除（CDC）；也可以再把這份副本推送到下游資料庫。Source 把變更帶進工作區，Sink 把 Source 的資料表複製出去。

規格

  • 使用一般的資料庫連線，支援 CDC
  • 來源有主鍵：Upsert 模式
  • 來源沒有主鍵：Append Only 模式
  • Sink 沿用 Source 的模式

限制

  • 模式在啟動後不能切換
  • 主鍵由 Plasma 從來源讀取，不能在 Plasma 裡另外設定

04

SQL Playground 與 SQL 方言SQL Playground · SQL Reference

直接對已連線的來源下 SQL，不必先把資料匯進來。跨不同廠牌的資料庫也用同一種 SQL 寫法，查好的語法可以「Save as View」存成 View。

規格

  • ANSI SQL 風格的 Plasma 方言，不是各來源資料庫的方言
  • 函式分類：字串、日期時間、陣列與 map、JSON、數字等
  • 同一套語法用在 SQL 編輯器、View 與資料產品

限制

  • 只允許 SELECT；INSERT、UPDATE、DELETE、CREATE、ALTER、DROP、TRUNCATE 一律拒絕
  • SQL 編輯器另外不接受 TRY_CAST、轉成 ARRAY／ROW 的 CAST、單獨的 GROUP BY ALL；改存成 View 即可使用

05

ViewsStandard · Materialized · Parameterized

把查詢存成可重複使用的 View。三種 View 差在什麼時候執行、結果存不存起來。

三種 View

  • Standard：每次查詢時才執行 SQL，不佔儲存空間
  • Materialized：觸發重新整理時執行一次，結果存成快照；可匯出成 HTTP。狀態 Initializing／Active／Inactive，同步狀態 Void／Syncing／Synced／Failed／Aborted
  • Parameterized：用 @name 當占位符，執行時代入參數；只能在專屬編輯器建立

限制

  • 執行超過 5 分鐘會被中止
  • 單次最多回傳 10,000 列（預覽、View Data、HTTP 匯出、參數化 API 都一樣），超過不會提示截斷；上限只有系統管理員能調整
  • Materialized 同步失敗時，仍可讀取上一次的快照

06

Data Blueprint資料匯出 Job 定義

可重複使用的匯出設定：把來源 View 的結果寫進目標資料表。Blueprint 定義「做什麼」，排程器決定「什麼時候做」。適合搬完整資料集，例如把 Informix 這類唯讀來源的資料複製出去。

規格

  • 寫入模式：Overwrite、Append、Truncate
  • 選項：Force Create Table（目標表不存在就建立）、Allow concurrent jobs（預設關閉）
  • 目的地：從工作區連線挑選，或直接輸入連線資訊（儲存前須通過 Verify Connection）
  • 不受 10,000 列上限限制
  • Execution History：每次執行的狀態、進度、錯誤行號與完整日誌

限制

  • 唯讀連線不會出現在目的地清單
  • 執行失敗不會改動目標表原有內容
  • 刪除 Blueprint 不會一併刪除排程，留下的排程會持續報錯
官方文件 →
07

排程器Scheduler

依時間或固定間隔自動執行 Data Blueprint。

規格

  • Once：只執行一次
  • Repeat Every：每 N 分鐘、小時、天或週
  • Calendar：每日、每週、每月、每年
  • 時間以瀏覽器時區輸入，以 UTC 儲存；記錄上次觸發時間與次數

限制

  • 不是 cron 語法
  • Calendar 只在 Start Time 設為 Immediately 時可用
  • 停機期間錯過的觸發不會補執行
  • 能否重疊執行由 Blueprint 的 Allow concurrent jobs 決定
官方文件 →
08

觸發器Triggers

一個工作完成或失敗時，自動接著做下一件事，把多個步驟串成流程（A → B → C）。

規格

  • 事件來源：Blueprint 的 Job 完成或失敗、Materialized View 同步完成或失敗
  • 動作：Sync View（重新整理 Materialized View）或 Spawn Blueprint（執行另一個 Blueprint）
  • 刪除來源時，觸發器會自動移除

限制

  • 同一事件有多個觸發器時，執行順序不保證
  • 停用後再啟用，不會補發停用期間的事件
  • 不偵測跨資源的循環（A → B → A），只對自我觸發顯示警告
官方文件 →
09

資料產品Data Products

把 View、Materialized View 或資料表發布成有名稱、可共享的資料集。其他工作區不必知道來源在哪個資料庫，用固定位址就能查詢。

規格

  • 每個資料產品有固定的 key
  • 從任何工作區查詢都是：SELECT * FROM data_product.default.<key>

限制

  • 位址直接指向來源，不是轉址；來源改名或刪除後，查詢會失敗

10

資料目錄Data Catalog

全平台共用的目錄，列出所有工作區發布的資料產品，像企業內部的資料市集。

規格

  • 卡片顯示所屬工作區、說明、類型與最後修改時間
  • 任何有 Plasma 帳號的人都能瀏覽
  • 目錄本身不存資料，卡片指向資料產品

限制

  • 目錄唯讀；能否編輯或刪除，看是不是來源工作區的成員
  • 來源被移除後卡片仍在，但查詢會失敗

11

MCPModel Context Protocol

把 Plasma 變成 MCP 伺服器。AI 助理不自己寫 SQL，而是從事先定義好的工具中挑一個、帶入參數執行，查得到什麼由工具決定。

規格

  • Group：一組工具
  • Tool：具名參數的 SQL，參數依型別、必填與允許值檢查
  • Access entry：對外 URL，各自設定驗證方式與到期日
  • 助理可用兩個動作：Search（用自然語言找工具）、Execute（帶參數執行）

限制

  • 單次執行最多 1,000 列，截斷時會告知客戶端
  • Search 需要管理員先設定含 embedding model 的 AI 連線
  • 工具屬於工作區，任何成員都能建立、編輯、刪除
官方文件 →
12

系統管理Administration

只有系統管理員能用：管理使用者、工作區、AI 連線與稽核記錄。

規格

  • 系統角色只有 admin 與 user；admin 可存取所有工作區
  • 使用者名稱以小寫字母開頭，只能有小寫字母、數字與底線，建立後不能改
  • 密碼至少 8 個字元，須含大寫、小寫，以及數字或特殊字元

限制

  • 刪除使用者會連同其私人工作區與內容一起刪除
  • 系統不會阻止刪除最後一個 admin，至少要保留一個
